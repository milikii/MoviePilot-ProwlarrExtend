# MoviePilot-ProwlarrExtend & SubtitleHunter

两个 MoviePilot 插件：一个把 Prowlarr 的索引器接进搜索，一个在入库后把中文字幕补齐。

主推 v3 版，代码在 `plugins.v3/`，清单是 `package.v3.json`。`plugins.v2/` 留给还在跑 MoviePilot v2 的人。

## ProwlarrExtend

### 为什么需要它

MoviePilot 内置的索引器只认 NexusPHP 系的国内站。Gazelle、UNIT3D、Luminance 这些架构的国际私有站（PTP、BTN、BHD 之类）进不来，而 Prowlarr 恰好能接管它们。

### 怎么工作

v3 不再做站点桥接，也不注册虚拟站点，SitesHelper 和站点表一概不碰。插件把自己注册成一个搜索来源：MP 搜索时带着空 site 调过来，插件拿当前选中的索引器向 Prowlarr 发一次聚合请求，多个 `indexerIds` 一起传，把结果转成 `TorrentInfo` 返回。索引器名保留真名，所以在 MP 里看到的是 BeyondHD、PassThePopcorn，而不是一堆虚拟站。

几个细节：

- 只搜启用、支持搜索、协议是 Torrent 的索引器。
- 整轮搜索共用一个总超时（默认 30 秒），拉目录和聚合检索都算在里面。
- 去重按「索引器 ID + guid」，guid 缺失时用下载链接；不同索引器的同名结果各自保留。
- 定时任务只刷新索引器目录，默认每天零点 `0 0 * * *`；刷新失败就保留上一次成功的快照。
- 结果带大小、做种数、发布时间、IMDb、分类和促销倍率；分页每页 100 条，页码按 offset 换算。
- 宿主同步和异步两种搜索入口都支持。
- 搜不到东西是正常结果，不当成错误；真要报错会带类别和 HTTP 状态码。
- 错误分类型记录：认证、限流、5xx、网络、超时各有标记，日志里的 API Key 会打码。

从 v2 升上来的话，之前桥接出来的虚拟站点不会自动清掉，想干净就手动删一下。

前置条件就一条：Prowlarr 里的索引器先配好、能正常搜。剩下的只是填地址和 Key。连接测试 `GET /api/v1/plugin/ProwlarrExtend/test`，运行状态 `GET /api/v1/plugin/ProwlarrExtend/status`。

配置项：

| 参数 | 说明 |
|------|------|
| 启用插件 | 总开关 |
| 使用代理服务器 | 走 MoviePilot 配置的代理访问 Prowlarr |
| 立即运行一次 | 打开即刷新一次索引器目录，不等 cron |
| 更新周期 | 5 位 cron，默认 `0 0 * * *`；旧的错误表达式会自动迁移 |
| Prowlarr 地址 | 如 `http://prowlarr:9696`；https 要带前缀 |
| Api Key | 在 Prowlarr → Settings → General → Security 里取 |
| 搜索超时（秒） | 整轮搜索总超时，含目录获取与聚合检索，5–120，默认 30 |
| 桥接索引器 | 多选限定搜索范围，**留空=全部**；先「立即运行一次」拉列表 |

## SubtitleHunter

### 它解决什么问题

字幕这事通常没人愿意手动管。要么媒体库里早就挂着能用的中文字幕，要么英文资源进来后什么也没有，得现找现压。

SubtitleHunter 接管入库完成（`transfer.complete`）那一刻，对整理后的目标目录跑一遍工作流：先看有没有中文字幕，没有就抽英文文本字幕，再翻成中文写到同目录。整个过程只在外挂文件上动手，不动 MKV / MP4 本体，也不影响 PT 做种校验。

工作流大致三步：

1. 用 `ffprobe` 列出外挂字幕和内嵌字幕流。
2. 用 `ffmpeg` 把内嵌文本字幕抽成外挂 `.srt` / `.ass`，按 Jellyfin / Emby 习惯改名，如 `.zh-Hans.srt`、`.en.forced.srt`、`.zh-Hans.ai.srt`。
3. 还是没有中文，就取英文文本字幕调模型翻一份，产出 `.zh-Hans.ai.srt`。

### 翻译这块

- 模型来源二选一。默认复用 MoviePilot 系统智能助手配置，也可以填自定义 OpenAI 兼容 `/chat/completions` 接口（Base URL / Key / 模型名 / 超时 / 代理）。
- 三种档位：`fast`（一段，最快）、`standard`（两段，均衡）、`quality`（三段，默认）。
- 默认产出 `.zh-Hans.ai.srt`，目标语言和翻译后缀都能在配置里改。
- 批次并发，默认每批 60 条 / 9000 字符、5 批。并发别一上来拉满，多数 OpenAI 兼容网关扛不住高 RPM，429 和 503 只会更慢；先 3–6，稳了再加。
- 翻译缓存按模型、影片上下文、术语表、批次、阶段、档位联合 key 存，中断后能接着上次的进度跑。缓存在插件数据目录的 `SubtitleHunter/translation_cache/`，不写进媒体库，也不缓存 API Key。
- 失败按错误分类处理：认证和参数错误直接失败不重试，429 先看 `Retry-After`，5xx 和网络问题指数退避。每个阶段另有总预算 `api_stage_budget`（默认 120 秒），请求和退避等待都算在里面，不会一个阶段卡几个小时。
- 输出逐条校验：每条字幕都得有译文或者明确的豁免理由（音效、音乐、空条目、本身就是中文），少一条整份失败、保留原文件。SRT 解析遇到坏块直接报错，不再悄悄丢条；翻译全程保住标签，成品先写临时文件、复验通过才替换。
- AI 自动术语表：开翻译前先整片过一遍抽专有名词，生成一张全片共享的术语表喂给三段翻译，避免跨批次出现「史塔克 / 斯塔克」。手填的术语表优先级更高，会覆盖同名的 AI 术语。
- 行长度后校验：按 Netflix 标准（英文每行 ≤42 字符、中文每行 ≤16 字符、每条 ≤2 行、CPS ≤15）检查每条译文，超标的丢回模型压缩措辞，改不动就用润色原文兜底，不阻塞输出。默认开。
- 句边界感知分批：接近批次上限时往后看 5 条找最近的句末标点切批，能在句末断就不在句中断。

约束：

- 只翻文本字幕：`.srt` / `.ass` / `.ssa`。PGS / VobSub 这类图形字幕能识别但没法直接翻，要 OCR。
- 环境里要能跑 `ffprobe` 和 `ffmpeg`。
- 接口返回的内容必须能解析成 JSON 数组，插件按所选档位并发调用模型。

### 手动跑和定时

除了入库自动触发，也可以开「立即运行一次」，或者配一条 cron 扫指定目录。同一时间只跑一个后台任务，跑到一半可以请求取消，取消在批次和视频边界生效。运行状态和最近 10 条历史会存盘，容器重启后还能看到上次的结果。

### 配置项

| 参数 | 说明 |
|------|------|
| 启用插件 | 总开关 |
| 入库后自动确保中文 | 监听 `transfer.complete`，对整理后的媒体库路径跑工作流 |
| 发送通知 | 任务开始、结束、失败时发通知 |
| 规范化外挂字幕命名 | 把同目录字幕改成媒体服务器更友好的命名 |
| 覆盖已有字幕 | 覆盖已存在的同名目标字幕 |
| 保留提取的中间字幕 | 关闭后，翻译成功会自动清理为翻译而提取的英文字幕 |
| 提取内嵌中文字幕 | 已有内嵌中文就抽成外挂并跳过翻译 |
| 启用 AI 翻译 | 没中文时调模型翻英文文本字幕 |
| 模型来源 | 系统智能助手（默认）或自定义 OpenAI 兼容 API |
| 自定义 Base URL / Key / 模型 | 仅自定义来源生效，默认 `https://api.openai.com/v1` |
| 自定义 API 使用代理 | 自定义来源是否走 MoviePilot 代理；系统来源按系统 `LLM_USE_PROXY` |
| 每阶段总预算秒数 | `api_stage_budget`，默认 120，范围 1–300，含请求与重试等待 |
| 翻译档位 | `fast` / `standard` / `quality`，默认 `quality` |
| 并发批次数 | 默认 5 |
| 每批字幕条数 / 每批最大字符 | 默认 60 / 9000 |
| 启用翻译缓存 | 默认开 |
| 启用行长度校验 | 默认开，按 Netflix CPL / CPS 标准压缩超长译文 |
| 定时执行周期 | 5 位 cron，留空禁用；如 `0 3 * * *` 每天凌晨 3 点跑一次 |
| 媒体目录或视频路径 | 「立即运行一次」和定时任务共用的扫描目标；多个路径用英文逗号分隔，按顺序处理 |
| 术语表 | 可选，每行一条 `原文=译文`，会与 AI 自动术语表合并（手填优先） |

### HTTP API

| 路径 | 方法 | 作用 |
|------|------|------|
| `/status` | GET | 看最近一次运行状态 |
| `/list?path=<dir or video>` | GET | 列出该目录或视频的字幕 |
| `/ensure` | POST | 异步跑「确保中文」工作流，`{"path": "<dir or video>"}` |
| `/extract` | POST | 提取指定视频的内嵌文本字幕，`{"path": "<video>", "stream_index": <n>}` |
| `/test` | GET | 测试当前 AI 翻译配置的连通性 |
| `/cancel` | POST | 请求取消当前后台任务（协作式，在批次和视频边界生效） |

接口都走 MoviePilot 的 API Key 鉴权。

### 速度建议

- 电影：`quality`、并发 5、每批 60 / 9000 字符。
- 剧集批量：`standard`、并发 5–8、每批 60–80 / 9000–12000 字符。
- 只想先有得看：`fast`，质量比三段低一点，但快。
- 第一次跑新网关时把并发压到 3，看日志里有没有 429，再往上调。

## 安装

在 MoviePilot 设置 → 插件 → 第三方插件仓库里加上本仓库地址，然后到插件市场装 **ProwlarrExtend** 和/或 **SubtitleHunter**。重启容器时会从 GitHub 拉最新代码，升级不用手动操作。

v3 版在 MoviePilot v3.1.9 上实机验过。还在 v2 上跑的话，装 `plugins.v2/` 对应的版本，配置项和用法基本一致。
